前言

这本手册能帮你做什么

很多人买了 AI 工具，用了一段时间之后发现——让 AI 写代码，写出来的东西要么跑不起来，要么跑起来了但不是自己想要的，要么改了三四轮还是一团乱麻，最后放弃了。

问题不在 AI 不够聪明，问题在于你不知道怎么跟 AI 说话。

这本手册就是解决这个问题的。我不会教你编程语法，不会让你背什么 Python 基础，也不会讲什么计算机原理。这本手册只做一件事：

给你一套标准化的流程 + 可以直接复制的提示词模板，让你照着做就能让 AI 产出可以直接运行的代码。

你需要的不是学会编程，你需要的是学会指挥 AI 编程。学编程要几个月甚至几年，学会指挥 AI 编程，认真看完这本手册，今天就能上手。

手册的核心逻辑

流程
模糊想法 → 拆解需求 → 套提示词模板 → AI 生成代码 → 复制运行 → 微调优化

适合的场景

  • 自动化处理 Excel 表格、批量重命名文件、定时发邮件
  • 写一个简单的数据统计脚本、生成图表
  • 做一个简单的网页、工具页面
  • 接外包单子，用 AI 帮你快速交付
  • 公司内部用的小工具、自动化流程

不适合的场景

开发大型商业软件、做复杂 App、学习编程本身——这些超出本手册范围，请知悉。

第三章

AI 写代码通用标准 5 步 SOP

这一章是整本手册最重要的部分。很多人用 AI 写代码失败，根本原因是提需求的方式不对。标准 5 步 SOP 就是解决这个问题的。

5 步 SOP 速查卡

1

需求拆解

功能 + 场景 + 限制条件，三件事想清楚再开口

2

套提示词模板

用本手册的万能模板填写需求，不要随意发散

3

AI 生成代码

要求完整代码 + 中文注释，不接受省略版

4

复制运行自测

先装依赖，再运行，对照检查清单逐项验证

5

微调优化

用固定句式让 AI 改 bug / 加注释 / 简化代码

第一步：需求拆解

在跟 AI 说话之前，先自己想清楚三件事：

  • 功能是什么？——不好的描述：「帮我处理一下 Excel」；好的描述：「读取 Excel，把 A 列重复行删掉，按 B 列数字从大到小排序，保存成新文件」
  • 场景是什么？——操作系统、文件格式、数据量、运行方式
  • 限制条件是什么？——不能用某些库、输出格式要求、性能要求
需求拆解练习模板 
【功能描述】：我要做什么
（例：批量把文件夹里所有 .txt 文件合并成一个文件）

【输入是什么】：数据从哪里来，是什么格式
（例：D盘/文本文件夹/ 下的所有 .txt 文件）

【输出是什么】：结果长什么样，保存在哪里
（例：合并后保存为 D盘/合并结果.txt，每个文件内容之间用分隔线隔开）

【运行环境】：什么系统，用什么语言
（例：Windows 10，用 Python）

【特殊要求】：有没有额外限制
（例：文件按文件名字母顺序合并，不是按修改时间）

第二步：套用万能提示词模板

通用代码生成提示词模板 
你是一个专业的 [Python/JavaScript/其他语言] 开发者。

请帮我写一段代码，实现以下功能：

【功能描述】
[填写你要做什么]

【输入说明】
[填写输入数据的格式、来源、示例]

【输出说明】
[填写期望的输出结果、格式、保存位置]

【运行环境】
操作系统：[Windows/Mac/Linux]
语言版本：[Python 3.11 / Node.js 18 等]

【特殊要求】
[填写任何额外限制，没有就写"无"]

要求：

4. 代码要有基本的错误处理，遇到问题给出友好提示

第三步：AI 生成代码示例

填好提示词发给 AI，你会得到类似这样的完整代码：

Python 
# 安装依赖：pip install openpyxl pandas
import pandas as pd
import os

def filter_high_sales(input_file, output_file, threshold=10000):
    """筛选销售额大于指定阈值的记录"""
    # 检查输入文件是否存在
    if not os.path.exists(input_file):
        print(f"错误：找不到文件 {input_file}，请检查路径是否正确")
        return

    # 读取 Excel 文件
    print("正在读取文件...")
    df = pd.read_excel(input_file)

    # 筛选销售额大于阈值的行
    filtered_df = df[df['销售额'] > threshold]
    print(f"共找到 {len(filtered_df)} 条销售额大于 {threshold} 的记录")

    # 保存到新文件
    filtered_df.to_excel(output_file, index=False)
    print(f"已保存到：{output_file}")

# 运行
filter_high_sales(
    input_file=r"D:/数据/销售数据.xlsx",
    output_file=r"D:/数据/高销售额记录.xlsx"
)

第四步：复制运行自测

自测检查清单：
☐ 代码有没有报错？
☐ 输出结果是不是我想要的？
☐ 输出文件有没有生成？
☐ 数据有没有丢失或者乱码？
☐ 边界情况：如果输入文件是空的，会怎样？

第五步：微调优化固定句式

改 bug 话术 
上面的代码运行后报了这个错误：
[把错误信息完整粘贴过来]
请帮我修复这个问题，给出完整的修改后代码。
加注释话术 
请给上面的代码每一个关键步骤加上中文注释，
让完全不懂编程的人也能看懂每一行在做什么。
简化代码话术 
上面的代码能不能简化一下？
我只需要核心功能，不需要那么多复杂的处理，
尽量让代码短一点、简单一点。

第七章

常见问题 FAQ

新手最容易遇到的问题，这里集中解答。每个问题都给了具体的操作步骤，不是泛泛而谈。

Q1：AI 生成的代码不能运行怎么办？

1

看报错信息

运行代码后，终端会显示红色的报错信息。把最后几行复制下来，这是最关键的部分。

2

对照报错类型表

看报错关键词，快速判断是什么问题：有 ModuleNotFoundError 先装库；有 FileNotFoundError 检查路径；有 SyntaxError 代码复制不完整，重新复制。

3

把报错发给 AI

用第五章的「报错修复请求」模板，把完整报错信息发给 AI，让它帮你修复。90% 的情况，这三步就能解决。

Q2：代码太复杂看不懂，怎么简化？

两个方法：

  • 方法一：让 AI 加注释——用第五章的「让 AI 加详细注释」提示词，让 AI 给每一行加上中文解释。
  • 方法二：让 AI 重新写简单版本——发送「上面的代码对我来说太复杂了，请帮我写一个功能完全一样但更简单的版本，去掉所有高级特性，用最基础的方式实现，代码行数尽量少，每行都加注释。」

Q3：如何让 AI 写出更稳定、少报错的代码？

在提示词里加上这几句话，效果明显：

稳定性增强附加要求 
额外要求：
1. 代码要有完善的错误处理，任何可能出错的地方都要用 try-except 捕获
2. 文件操作前先检查文件是否存在
3. 关键步骤打印进度提示，让我知道程序在做什么
4. 不要用可能在不同系统上行为不一致的写法
5. 代码要能在 Python 3.8 到 3.12 的任意版本上运行

Q4：不懂语法，怎么判断 AI 写的代码靠不靠谱？

  • 让 AI 自己解释——发送「请用大白话解释这段代码的工作流程，不要用专业术语」，如果解释和你的需求对得上，代码大概率是对的。
  • 用小数据测试——先用少量数据（比如 5 行 Excel）测试，确认结果正确后再用全量数据。
  • 让 AI 列出风险——发送「这段代码有没有什么潜在的问题或者风险？比如数据丢失、文件被覆盖、处理结果不准确等，请列出来并说明如何避免。」

Q5：AI 每次给的代码都不一样，哪个版本对？

AI 有一定的随机性，同样的提示词可能给出不同的实现方式。判断哪个版本更好：代码更短更简单的通常更好维护；有错误处理的比没有的更可靠；用常见库（pandas、requests）的比用冷门库的更稳定。

第八章

新手避坑红线

这一章说的是「不能做的事」，比「能做什么」更重要。

8.1 禁止做的高风险代码场景

以下场景坚决不碰，不管客户出多少钱：

❌ 涉及他人隐私数据的爬虫——爬取用户手机号、身份证、地址等，涉及违法。
❌ 绕过验证码、模拟登录的脚本——很多平台明确禁止，轻则封号，重则法律风险。
❌ 批量注册账号、刷量、刷评论——本质是作弊，涉及不正当竞争。
❌ 破解、逆向、绕过付费验证——侵权行为，不碰。
❌ 涉及金融交易的自动化脚本——没有专业背景的情况下，一个 bug 可能造成重大损失。
婉拒高风险需求话术 
您好，这个需求涉及到 [简单说明原因，如 用户隐私数据/平台规则限制]，
我这边没办法接这类单子，抱歉。

如果您有其他需求，欢迎继续沟通。

8.2 避免过度依赖 AI 完全不动脑

AI 是工具，不是大脑。有几件事你必须自己做：

① 需求要自己想清楚——AI 不知道你的业务场景，需求模糊，代码就会跑偏。
② 结果要自己验证——AI 写的代码可能有逻辑错误但不会报错，必须用已知数据验证结果是否正确。
③ 不要把 AI 的代码直接用于生产环境——涉及真实数据的脚本，一定要先在测试数据上跑通。
④ 重要数据操作前先备份——任何会修改或删除文件的脚本，运行前先备份原始数据。

8.3 接单避坑：客户无理需求怎么婉拒

  • 坑一：需求无限扩展——每次改动前确认是否在原需求范围内，超出范围的额外报价。
  • 坑二：要求「包教会」——明确说明编程教学不在服务范围内。
  • 坑三：要求「永久维护」——明确说明售后期限（3 天或 7 天），超出期限的维护需要额外付费。
  • 坑四：先做后付——新客户不要先做后付，至少收 50% 定金再开始。
  • 坑五：需求描述极其模糊——客户说「帮我做个系统」但说不清楚具体要什么，这种单子不接或者先收需求分析费。
